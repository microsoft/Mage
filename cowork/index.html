Abstract

Effective computer-use agents should seamlessly combine visual GUI interaction with code and terminal execution within a single policy. We introduce Mage-VL-Cowork, a 4B hybrid computer-use agent trained from an intermediate Mage-VL checkpoint through an end-to-end, progressive five-stage curriculum across midtraining, SFT, and RL. Mage-CUA-Forge powers this curriculum with reusable, skill-conditioned generation workflows and application-specific preparers, synthesizing 293,806 desktop and web tasks across 6,915 skills while reducing recurring per-task expenditure by 82.6%. Rather than directly distilling a default teacher, we evolve its harness and instantiate specialized GUI, terminal, and hybrid configurations to collect stage-specific supervision, including 318,837 retained hybrid trajectories. The final policy reaches 66.0% on OSWorld-Verified under a 50-step budget, outperforming reported results of larger agents including Muse Glimmer-30B and Qwen3.6-27B. Relative to Hybrid SFT, online RL adds 10.16 percentage points while reducing mean model calls by 13.0% and output tokens by 25.4%.

Evolve the harness before collecting the corpus

A strong teacher does not automatically make a strong hybrid agent. We refine the scaffold, tool interfaces, prompts, and terminal execution environment before large-scale rollout. Evolution is as much pruning as growth: remove redundant action routes and provide application-level libraries. Specialized GUI, terminal, and hybrid CUA harnesses then roll out the same synthesized tasks to collect demonstrations for different training stages. The final student learns channel routing inside a single policy—not an external orchestrator.

GUI CHANNEL

Act on what the screen shows.

Use screenshot-grounded mouse and keyboard actions for visual layouts, rendered output, and live application state.

TERMINAL CHANNEL

Work directly with structured files.

Use code, command-line tools, and application libraries to manipulate documents, spreadsheets, and presentations.

The same policy chooses the channel at each turn—and switches when the task calls for it.

Optimize the teacher’s execution upstream; carry better hybrid behavior into every retained demonstration.

More tools are not always better. On the same 672 held-out multi-application tasks, the GUI + coding teacher scores 92.0%, versus 89.6% with an added accessibility channel. The corresponding 4B students score 37.6% and 25.1%—a 12.5 pp gap. See the paired comparison ↓

Author a workflow once. Generate many executable tasks.

Mage-CUA-Forge replaces per-task agent construction with reusable, skill-conditioned workflows. Shared application preparers create files and desktop state; coordinated branches produce an instruction, environment setup script, and evaluation rubric. For web and cross-application tasks, synthesized InfiniteWeb environments and high-fidelity replicas built upon and expanding WebHarbor provide resettable local state. Student feedback expands and refines the skill taxonomy across generation rounds.

38.24% of tasks span multiple applications. Application counts are multi-label; file-family shares use 877,608 task–file references. InfiniteWeb tasks are reported separately.

Build both capabilities before learning to combine them

Starting from an intermediate 4B Mage-VL checkpoint, the specialize-then-unify curriculum first develops visual grounding, reasoning, structured tool calling, GUI execution, and coding and terminal capabilities. Hybrid CUA SFT then teaches a single policy to combine its channels, followed by online hybrid RL with verifiable rewards.

GUI-Oriented Midtraining → GUI Agent SFT → Coding & Terminal SFT → Hybrid CUA SFT → Online Hybrid RL

The model first develops two capable action channels, then learns to select and combine them. This avoids learning hybrid routing simply as a workaround for weak GUI execution.

Browser transfer before RL · 58.6% on WebVoyager-Static

The 4B Mage-VL-Cowork-SFT model achieves 58.6% success (377/643 tasks), ranking second among the evaluated models behind the specialized browser agent Fara1.5-4B (68.0%). It outperforms larger models including Qwen3-VL-8B-Thinking (53.7%) and Qwen3.5-9B (53.3%).

WebVoyager-Static reconstructs all 643 tasks across 15 websites using self-hosted replicas built upon and substantially extending WebHarbor. Verification checks page visits and required UI operations, then compares the answer and backend database state against ground truth—not just the final screenshot.

Midtraining design · grounding, reasoning, and tool calling

Stage 1 separates the click-only grounding prompt from the full agent schema and deduplicates repeated target locations within same-screenshot packed sequences. The adopted recipe masks the interior of <think> rationales while supervising the delimiter tags and tool calls, preserving the reasoning format while focusing the loss on tool syntax and grounding.

Single Step Cowork Bench: 342 representative desktop interaction steps spanning eight GUI action primitives. It jointly checks reasoning/tool-call syntax, action type and arguments, and spatial hit accuracy. This is a diagnostic specification, not an additional reported aggregate score.

Compact working memory · recent screenshots + folded action history

Each context retains the three most recent screenshots and four complete responses, with older steps compressed into imperative Action: summaries immediately after the system prompt. A response combines a grounded <think> rationale, an Action: summary, and the executed <tool_call>. Step-level rationale synthesis uses task context, before/after screenshots, and the executed tool call to produce this consistent format.

RL progression · all 33 recorded evaluations
Rollout-as-a-Service · asynchronous desktop RL infrastructure

Desktop environments, model inference, and policy optimization scale separately. The infrastructure integrates PoLar, Slime, Azure Relay, and Azure VM Scale Sets, with SGLang serving model requests. Asynchronous rollouts let completed tasks advance training without waiting for the longest desktop episodes.

Reference deployment: 1,120 GUI slots on 70 CPU hosts, with 24 B200 GPUs for training and 8 for inference. The report describes bounded policy lag and truncated importance sampling.
